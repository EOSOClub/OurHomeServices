# 📬 Proton Mail Bridge

A headless [Proton Mail Bridge](https://proton.me/mail/bridge) in Docker. Proton
encrypts mail end-to-end, so ordinary mail clients can't read it directly; the
Bridge decrypts it locally and serves it over plain IMAP/SMTP. Here, that lets
[Paperless-ngx](../paperless) pull bill and receipt emails from your Proton inbox.

> [!NOTE]
> The Bridge needs a **paid Proton Mail plan**. Free accounts can't use it.
> Using a different mail provider? Skip this stack and point Paperless at that
> provider's IMAP server instead.

| Address (inside Docker) | Protocol |
| --- | --- |
| `protonmail-bridge:143` | IMAP |
| `protonmail-bridge:25` | SMTP |

Nothing is published to the host. Only containers on `ourhome_net` can reach it.

## 🚀 Setup

**1. Build and log in** (once):

```bash
cd proton-bridge
docker network create ourhome_net                    # skip if it already exists
docker compose build
docker compose run --rm protonmail-bridge init
```

At the `>>>` prompt:

```
>>> login            # your Proton email, password, and 2FA code if enabled
>>> info             # prints the Bridge's IMAP/SMTP username and password: copy them
>>> exit
```

> [!IMPORTANT]
> The password `info` prints is **generated by this Bridge**. It is not your
> Proton password, and not the one a desktop Bridge shows you. Paperless needs
> this one.

**2. Start it:**

```bash
docker compose up -d
docker compose logs -f protonmail-bridge    # should start and sync, with no ">>>" prompt
```

Your login is saved in `./state/` (gitignored), so restarts and rebuilds don't
need a new login.

## 🔌 Use it from another container

Join `ourhome_net`, then connect with:

| Setting | Value |
| --- | --- |
| Host | `protonmail-bridge` |
| IMAP port | `143` |
| SMTP port | `25` |
| Security | **None** |
| Username / password | From `info` above |

<details>
<summary><b>Why "None" for security?</b></summary>
<br>

The Bridge's self-signed certificate is issued for `127.0.0.1` only, so TLS to
the hostname `protonmail-bridge` fails verification. The Bridge still accepts
logins without TLS. That's acceptable here because the traffic never leaves the
host's internal Docker network, and the Bridge talks to Proton with end-to-end
encryption.

That's also why this stack publishes **no ports**. Don't add any.

</details>

## 🛠️ Troubleshooting

| Symptom | Fix |
| --- | --- |
| `error while loading shared libraries: libfido2.so.1` (exit 127) | The Bridge updated itself to a binary that needs a library the image lacks. `image/Dockerfile` adds `libfido2`. If a future update needs another one (same error, different name), add it to the `apt-get install` line and run `docker compose build`. |
| Clients get `Connection refused` | Wrong port. Use **143** (IMAP) / **25** (SMTP). The `1143` / `1025` in the Bridge's own logs are internal ports, unreachable from other containers. |
| A `>>>` prompt in the logs, or "no keychain" / "vault will not be encrypted" | The saved login is gone. Reset and log in again (below). |
| `Failed to parse address [Error offset=…]` while syncing | Harmless. A malformed address header on one message; the Bridge skips it. |

**Reset the login:**

```bash
docker compose down
find state -mindepth 1 ! -name .gitkeep -delete       # PowerShell: Get-ChildItem state -Force -Exclude .gitkeep | Remove-Item -Recurse -Force
docker compose run --rm protonmail-bridge init        # login → info → exit
docker compose up -d
```

The Bridge generates a **new** password after a reset, so update it in Paperless
(*Mail → Mail accounts*).
